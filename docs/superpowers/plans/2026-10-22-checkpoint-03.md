# Checkpoint 03 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fechar as lacunas do enunciado do Checkpoint 3: navegação com parâmetros e voltar, feedback de sucesso, validação, sessão expirada e documentação final.

**Architecture:** Stack nativo aninhado apenas na rota `Cadastro` do drawer (Lista → Detalhe → Formulário, com `id`/`tipo` como parâmetros de rota). Validação pura em `utils/validacao.ts` (única parte com teste automatizado). 401 tratado em `services/api.ts` por callback registrado no `AuthContext`.

**Tech Stack:** Expo SDK 57, React Native 0.86, TypeScript, React Navigation 7 (drawer 7.14, native-stack 7.19), Node 24 (`node --test` com type stripping).

**Spec:** `docs/superpowers/specs/2026-10-22-checkpoint-03-design.md`

- Indentação de 4 espaços; `const[estado, setEstado] = useState(...)` como nas telas atuais.
- Nenhuma dependência nova (native-stack já está instalado).
- Verificação de cada task: `npx tsc --noEmit` sem erros; tasks com UI também `npx expo export --platform android --output-dir <scratchpad>/dist` sem erros.
- Commits terminam com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Número com vírgula ("2,5") e lixo ("abc", "1.2.3", "") — deve aceitar o primeiro e rejeitar os outros com mensagem clara (teste em Task 1).
2. Data "2026-02-30" / "22/10/2026" — rejeitar com mensagem de formato (teste em Task 1).
3. Erro de 2FA (código errado, 401 com token temporário) não pode derrubar o usuário para a tela de e-mail — o callback de sessão só age com usuário logado (Task 3, verificação manual).
4. Voltar do Android dentro do Cadastro desempilha (Formulário → Detalhe → Lista) em vez de sair para Perdas (Task 4, manual).
5. Mensagem de sucesso vinda por parâmetro não reaparece ao voltar para a tela depois (Task 4, manual).

**Interfaces:**

- [ ] **Step 1: Write the failing test** (`node:test` + `node:assert/strict`, importando `./validacao.ts`)

```ts
test('converterNumero aceita ponto e vírgula', () => { assert.equal(converterNumero('2,5'), 2.5); assert.equal(converterNumero(' 10 '), 10); });
test('converterNumero rejeita vazio e lixo', () => { for (const t of ['', '  ', 'abc', '1.2.3', '2,5kg']) assert.equal(converterNumero(t), null); });
test('dataValida aceita AAAA-MM-DD real', () => { assert.ok(dataValida('2026-10-22')); assert.ok(dataValida('2024-02-29')); });
test('dataValida rejeita formato e dia inexistente', () => { for (const t of ['22/10/2026', '2026-2-1', '2026-02-30', '2025-02-29', '']) assert.equal(dataValida(t), false); });
```

- [ ] **Step 2:** `npm test` → FAIL (módulo inexistente)
- [ ] **Step 3:** Implementar. `converterNumero`: trim, troca `,` por `.`, `Number()`, `null` se vazio ou `NaN`. `dataValida`: regex `^\d{4}-\d{2}-\d{2}$` + `new Date(Date.UTC(a, m-1, d))` conferindo ano/mês/dia de volta.
- [ ] **Step 4:** `npm test` → 4 pass; `npx tsc --noEmit` → sem erros
- [ ] **Step 5: Commit** — "Adiciona funcoes de validacao de numero e data com testes"

- [ ] **Step 1:** `CadastroNavigator`: `createNativeStackNavigator<CadastroStackParamList>()`, header com `cores.superficie`/`cores.textoTitulo`/`fontes.tituloSemiNegrito` (mesmo do drawer), `contentStyle: { backgroundColor: cores.fundo }`. Títulos: Lista "Cadastro" com `headerLeft: () => <DrawerToggleButton tintColor={cores.textoTitulo} />`; Detalhe "Detalhes"; Formulário título dinâmico via `options={({ route }) => ...}`: "Novo produto" / "Editar produto" / "Novo ingrediente" / "Editar ingrediente".
- [ ] **Step 2:** `CadastroListaScreen`: mover de `CadastroScreen` a alternância Produto/Ingrediente e a lista (só `listarProdutos`/`listarIngredientes`); recarregar com `useFocusEffect(useCallback(...))`; botão `Botao` "Novo produto"/"Novo ingrediente" → `navigate('CadastroFormulario', { tipo: modo })`; card com `onPress` → `navigate('CadastroDetalhe', { tipo: modo, id })` e texto "Toque para ver detalhes"; sem botões Editar/Excluir. Conteúdo em `ScrollView` com padding 20.
- [ ] **Step 4:** `CadastroFormularioScreen`: mover os dois formulários e `salvarProduto`/`salvarIngrediente` de `CadastroScreen`; carregar categorias/unidades (e o item, se `id`) ao montar, com `Carregando`/`ErroCarregamento`. Ao salvar: criar → `popTo('CadastroLista', { mensagem: '... cadastrado com sucesso!' })`; editar → `popTo('CadastroDetalhe', { tipo, id, mensagem: 'Alterações salvas com sucesso!' })`. Botão secundário "Cancelar" → `goBack()`. Conteúdo em `ScrollView` + `KeyboardAvoidingView` (mesmo padrão do `TelaLista`).
